# wehub-start

这个仓库用 Agent Note 做任务交接。本命令帮你接手工作:先看现状,再顺着人的意图开工。

## 话术纪律(全程遵守)

wehub、.wehub 目录、task.json、log.md、plan.md、skill 名、命令名、任务 id、
draft/in_progress/done 这类状态码都是你的后台工具,不是聊天话题。
对人只说业务语言:说"这件事刚准备开始/正在做/已经收尾"、"目标、范围、怎样算完成"、
"上次做到哪、下次从哪继续"。不要说"空模板"、"交接日志没内容"、"状态是 draft"。
后台命令静默执行,不要向人宣布"我要运行某某命令";人主动问机制时才解释。

## 第一步 · 摸现状(静默执行,按结果说话)

执行 `node .wehub/scripts/wehub.cjs task list`:

- **有未完结任务** → 用口语汇报:每个任务一句话(在做什么、进展到哪、下次从哪继续)。
  task id 只供你后台接手用,不要念给人。计划还没填时,说"这件事还没确认目标、范围和怎样算完成",
  不说"计划书是空模板";没有交接记录时,说"上次还没真正开工",不说"交接日志没内容"。
  显示有人在做但看起来没人跟进的,说明"可能是上次中断了,我可以还原上下文继续"。
  然后结合人本轮的请求问:继续其中一个,还是做新的事?
- **没有任务、且人已经说了想做什么** → 什么都不用汇报,直接进第二步。
- **没有任务、人也没说要做什么** → 问人想做什么即可。

## 第二步 · 顺着人的请求走(体量由你判断,不把机制选项抛给人)

- **一句话能做完的小事**(问答、一次性小改动)→ 直接动手做,做完即止。
  不要拿"开不开任务"这类机制概念去问人,也不要解释"这不会产生记录"。
- **值得跟踪的工作**(要构建的功能、多步骤或多次会话才能完成的改动)→ 用业务语言提议:
  "这个我建议当成一件完整工作来跟,先和你对齐最关键的一点再动手?"人同意后:
  1. 执行 `node .wehub/scripts/wehub.cjs task new "<标题>" --slug <english-slug>`
     (slug 是英文小写连字符,由你根据标题意译;静默执行)。
  2. 按 wehub-define skill 产出计划书:需求清楚直接写好,把内容展示给人批准;
     说不清就一次只问一个最关键的业务问题。对人说"我们先确认目标、范围和怎样算完成",
     不说"我要写 plan.md"。
  3. 人批准后执行 `node .wehub/scripts/wehub.cjs task start <id> --agent claude-code`,
     读它输出的计划、上一段交接、项目经验,向人做接手摘要后开工。
- **拿不准体量** → 问业务问题判断("是想要一个完整能用的,还是先跑通个雏形?");
  仍拿不准就先按小事直接做,做着发现变大了再提议立任务跟踪。

(继续已有任务时同样走 task start,读输出、做接手摘要:上一段做了什么、
放弃了什么、从哪继续。输出里带上一棒的实际改动清单,先和交接记录核对,
对不上的向人指出;"review 重点"有内容时,先看对应代码再动手——接手即互检。)

## 第三步 · 工作中与收尾

遵守 .wehub/workflow.md 的行为约定。收尾时用 wehub-handoff skill 写交接——
对人说的是"这段工作我交接一下,下次能接着做",不念文件名和字段名。

(脚本执行失败时,读 .wehub/workflow.md 按其规则手工完成同样的事,别卡住。)
