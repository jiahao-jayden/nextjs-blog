# wehub-handoff

这个仓库用 Agent Note 做任务交接:你停下之后,接手的可能是另一台机器上的另一个 agent,
它看不到你的会话,只能看到文件。所以收尾不是直接停下,而是把"只有你知道的上下文"写进文件再走。

你接手任务(task start)时,脚本已经给你建了一份工作区 `wip-<人名>.md`
(`## H<n> …` 小节 + 六个空字段)。只有你会碰它。收尾就是把它填完整,然后跑 record 归档。

先说一条贯穿全程的话术规矩:工作区、六字段、resume 这些是你的后台工具,
对人说话不要念它们的名字。说"我把这段工作交接一下,方便下次接着做",
不说"我要填工作区的六个字段"。

## 第一步 · 先问人

向人提议:"这段工作我交接一下?下次谁接手都能直接继续。"人确认再继续;人说不用就停止。

## 第二步 · 填写你的工作区 wip-<人名>.md

打开你的工作区 `wip-<人名>.md`,把六个字段填好:

- **类型** / **摘要** / **决策与放弃** / **验证** / **遗留与下一步** / **review 重点**
- 每行都必须有内容;确实没有就写"无",但不能删行、不能留 TODO/TBD 这类占位。
- "验证"只能是两种写法:实际跑过的命令和结果;或 `not_run: <没跑的原因>`。
- "review 重点"点到具体位置时写成 `路径:行号`(如 `src/auth.ts:42`),人和平台好定位。
- 不要写 key、token、密码;疑似机密的内容用 <redacted> 替换,并在"review 重点"里说明。

填完自查一遍:跑 `git diff <小节头里的 sha>..HEAD` 看看这段时间实际改了什么——
改动很大而"决策与放弃"却写着"无",多半是忘了,先回忆补上。
改动多、还没跑过验证时,可以派 wehub-check subagent 去跑 lint/测试、顺手修小问题,
把结果写进"验证"字段。

## 第三步 · 用 record 收尾

```
node .wehub/scripts/wehub.cjs record <id> --agent claude-code --resume-hint "<下一棒的第一个动作>"
```

续接提示要写成**下一棒接手后的第一个动作**,不是状态描述:
写"先跑 auth 测试确认并发问题还复现,再看 refresh 的锁",
不写"做到一半了"——接手的人照着第一句就能动手。

脚本会检查六个字段是否填齐;通过后补上 **resume** 行(已交接标志)与 **end** 行(结束 sha),
把这一节归档进 log.md、删掉你的 wip,并 git add。检查不过会告诉你缺什么,照提示补齐重跑即可。
record 不会改 task.json 的 status——任务是否完结由人决定,不由这个命令决定。

## 第四步 · 向人交底

用业务语言收口,不念文件名和字段名:

- 告诉人"下次从哪继续"(就是你写的续接提示那句话),让人过目。
- 顺带确认:要不要 git commit / 开 PR;如果目录还不是 git 仓库,要不要 git init。
- 问一句"这个任务算完成了吗,还是先放着?"——人明确说完成(或不做了)才执行
  `node .wehub/scripts/wehub.cjs task done <id>`(不做了加 --cancelled),执行完用一句话确认:
  "好,这个任务我标记完成了。"

脚本失败不要卡住:按 .wehub/workflow.md"文件格式"一节手工完成同样的事——把 wip 那节
(补上 **resume** 与 **end** 行)挪进 log.md 的 begin/end 标记之间再删 wip。完整规则以 .wehub/workflow.md 为准。
