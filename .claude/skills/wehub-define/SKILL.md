# wehub-define

每个任务开工前都要有一份人批准过的计划书(plan.md)。本 skill 管这件事:

- 需求清楚 → 直接跳到"第四步 · 写计划书",写完请人批准。
- 需求模糊 → 从第一步开始:先对齐、再调研、最后写——不是直接写代码,也不是闷头查资料。

话术纪律:plan.md、承诺区、research/ 这些是你的后台机制,对人只说业务语言——
说"目标、范围、怎样算完成",不说文件名和区块名;请人批准时把计划内容直接展示在对话里,
不要让人自己去打开文件。后台命令一律静默执行。

## 想清楚再动手(三条思维规则,贯穿全程)

1. **先重述问题,再想方案。** 把需求剥掉实现细节,重述成"要解决什么问题":
   "加个 Redis 缓存"其实是"数据加载太慢"。人给的可能是方案,你要找到方案背后的问题——
   解错了问题,方案再好也白做。
2. **分清硬约束和软约束。** 物理/法律/技术边界、定死的预算和期限是硬的,照办;
   "一直都这么做、现有架构如此、行业惯例"是软的,默认可以挑战——
   觉得不对就提出来,别照单全收。
3. **两个方案都行时,选假设更少的。** 依赖的猜测更少、活动部件更少的方案优先。
   但简化不能删掉现实:砍掉某个部分之前,先确认没有哪条硬约束需要它。

## 第一步 · 先问人(仅需求模糊时)

判断标准:这个需求的目标(解决什么问题)、边界(不做什么)、验收(怎样算完成)
能不能说清楚?说不清就是模糊。
向人提议:"这个需求我先和你对齐几个问题?"人确认再继续。

## 第二步 · 提问和调研交替进行

提问的规矩:

- 仓库能回答的问题不许拿去问人:先读代码、测试、配置、文档、已有任务的记录;
  只把"产品意图、偏好、范围、风险取舍"这类查不出来的问题留给人。
- 一次只问一个问题,每个问题带齐四件东西:要做什么决定、这个决定为什么重要
  (影响到什么)、你的推荐答案、选别的选项会有什么代价。让人做选择题,不做问答题。
- 问不到人、或信息就是不全时,不许卡住:写下你的假设,按最合理的解释继续推进,
  并在 plan.md 的"待定问题"里注明"如果 XX 事实不成立,这个方案要翻盘"。

调研的规矩:

- 每查清一个主题,把发现写成一个文件:`tasks/<任务目录>/research/<主题>.md`
  (文件名小写连字符,一个主题一个文件)。不要只留在聊天里——聊天记录会被压缩丢失,文件不会。
- 问题已经明确、但查起来工作量大(要读很多代码或资料)时,可以派 wehub-research
  subagent 去查:派遣时第一行写 `Task: <任务id>` 和要查的问题,你只接收结论。
  注意:需要和人对话的环节(提问、提议、请人拍板)不能外包给 subagent。

## 第三步 · 决定调研产物放哪

- 只和当前任务有关的材料(方案对比、API 摸底)→ 留在 `research/` 目录,你自己写,不用问人。
- 对整个项目长期有用的结论(约定、选型、坑)→ 按 wehub-remember skill 向人提议
  存进 `.wehub/knowledge/`,人同意后再写。只提炼一两行结论,全文留在 research/ 里。
- 调研本身很大(产出会被多个任务反复用)→ 提议单独立成一个任务。拿不准就问人。

## 第四步 · 写计划书(plan.md)

**承诺区(目标/边界/验收,必填):** 把聊清楚的结论写进去,人确认。
确认之后这三节冻结:再改范围必须人明确同意。

**步骤区(## 步骤,按需):** 一棒能做完的小任务直接删掉这一节。预计要多段接力、
或步骤之间有依赖顺序的任务,和人确认一份步骤清单:

- 内容:有序的 checkbox 清单,每步带一行"怎么验证"(跑什么命令、看什么结果);
  有风险的步骤注明回滚方式;还没定的问题列在末尾。
- 性质和承诺区不同:步骤是活的。做完打勾、根据实际情况调整,都不用人批;
  但如果调整意味着目标/边界/验收变了,必须先回承诺区走人批——步骤服从承诺。

**定稿收敛(请人批准前做一遍):** 边聊边写的 plan.md 会留下重复的事实、
已经回答掉的问题、"我目前的理解"这类临时段落。请批前把它无损重写一遍:
重复的合并、已解决的删掉、临时记录折叠进正式章节;所有决策、约束、
文件位置引用一个都不能丢。给人看的是定稿,不是草稿。

**请批前自检(四条都过才开口):**

- [ ] 验收标准是可验证的(能跑命令、能看结果,不是"体验更好"这种空话)
- [ ] 仓库能回答的问题都已经自己查完了
- [ ] 剩下的待定问题真的只关乎人的意图和取舍,不是偷懒没查
- [ ] 收敛过了:没有重复事实,没有已解决还挂着的问题

人批准计划书后执行 `node .wehub/scripts/wehub.cjs task start <id> --agent claude-code` 进入实现。

完整规则以 .wehub/workflow.md 为准。
